### Architecture Decision Record
### docs/architecture/decisions/ADR-011-PRODUCTION_ENGINEERING_STANDARDS.md

**Date:** 2025-11-15  
**Status:** ACCEPTED — ENFORCED

**Scope:** All code produced for Aether AI OS

## THE CORE PRINCIPLE

**Aether is a five-year engineering investment. Every line of code written today is a commitment
the project carries indefinitely. Code that works but is wrong is worse than no code — it
creates the illusion of completeness while embedding future failure. There is no schedule
pressure that justifies low-quality code in a personal project with no external deadline.**

---

## 1. SCOPE AND PURPOSE

This document defines the minimum acceptable standard for every artifact produced in the Aether AI OS project. These standards apply universally:

- Code authored by the developer
- Code generated by AI tools (Antigravity IDE, Claude, Gemini)
- Database migrations
- Configuration files
- Infrastructure scripts
- Documentation

No artifact is exempt. AI-generated artifacts require the same standard as human-authored artifacts. The mechanism of generation does not determine the quality bar — the project's long-term integrity does.

---

## 2. ZERO-TOLERANCE VIOLATIONS

The following violations result in immediate rejection of any code contribution. They are not subject to discussion, exception, or override. Code containing these violations does not enter the codebase under any circumstance.

**ZT-1: Silent exception handling**  
Any code path that catches an exception and does not re-raise, log, or handle it explicitly.

**ZT-2: Emoji in code artifacts**  
Any emoji character in Python files, TypeScript files, SQL files, YAML configuration files, shell scripts, log messages, error messages, variable names, function names, or class names. See Section 3.1 for precise definition.

**ZT-3: Hardcoded secrets**  
Any API key, password, token, or credential appearing in source code, configuration files, or scripts that are committed to the repository.

**ZT-4: Direct provider imports outside the LLM module**  
Any import of `anthropic`, `openai`, `litellm`, or `google.generativeai` outside of `aether/llm/_providers/`.

**ZT-5: Direct database access outside the memory module**  
Any import of `qdrant_client`, `sqlalchemy`, `aiosqlite`, or `sqlite3` outside of `aether/memory/_stores/`.

**ZT-6: Missing type annotations on public functions**  
Any public function or method lacking complete parameter type annotations and return type annotation.

**ZT-7: Stub implementations presented as complete**  
Any function containing only `pass`, `...`, or a hardcoded return value that is represented in a commit or pull request as a complete implementation.

**ZT-8: Bare `except` clauses**  
Any `except:` clause without an explicit exception type.

**ZT-9: `print()` in production code**  
Any `print()` statement in `aether/`, `services/`, or `migrations/`. All output goes through `structlog`.

**ZT-10: Hardcoded model names in application logic**  
Any string literal containing an LLM model name (e.g., `"claude-opus-4-6"`, `"gpt-4o"`, `"gemini-2.0-flash"`) outside of `aether/llm/` and `config/`.

## 3. CODE QUALITY STANDARDS

### 3.1 Emoji Policy — Precise Definition

**Emoji** for the purposes of this standard means:
- All Unicode characters in the emoji code blocks (U+1F300 to U+1FAFF, and related ranges)
- Text emoticon sequences (`:smile:`, `:fire:`, `:rocket:`, etc.)
- Decorative Unicode symbols used as visual embellishment in code

**Emoji is forbidden in:**
- All Python source files (`.py`)
- All TypeScript source files (`.ts`, `.tsx`)
- All SQL files (`.sql`)
- All YAML configuration files (`.yaml`, `.yml`)
- All JSON files (`.json`)
- All shell scripts (`.ps1`, `.sh`, `.bat`, `.cmd`)
- All log messages and log format strings
- All error messages and exception messages
- All variable names, function names, class names, module names
- All inline code comments
- All docstrings
- All commit messages
- All git branch names and tag names

**Permitted Unicode characters in code and documentation:**
- Mathematical operators: `×`, `÷`, `≤`, `≥`, `≠`, `∞`
- Box-drawing characters: `─`, `│`, `├`, `└`, `┐`, `┘`, `┌`, `┤`, `┬`, `┴`, `┼`
- Logical symbols: `→`, `←`, `↑`, `↓`, `↔`, `⇒`
- Check and status markers in documentation checklists: `□`, `■`, `✓`, `✗`

**Permitted in user-facing documentation only** (`README.md`, `docs/guides/`):
- Navigation aid symbols used sparingly to indicate section type (warning, note, tip)
- No decorative or celebratory emoji

**Rationale:** Emoji in code signals informality. Informality in a five-year engineering project creates the wrong tone, introduces encoding issues in some tools, and is inconsistent with production engineering practice. Code is communication between engineers, not a social medium.

### 3.2 Forbidden Patterns — Exhaustive Reference

The following patterns are forbidden in all production code. The list is comprehensive, not illustrative.

#### 3.2.1 Exception Handling Violations

```python
# FORBIDDEN — bare except
try:
    result = operation()
except:
    pass

# FORBIDDEN — catches Exception, does nothing
try:
    result = operation()
except Exception:
    pass

# FORBIDDEN — catches Exception, silently returns None
try:
    result = operation()
except Exception:
    result = None

# FORBIDDEN — catches Exception, swallows context
try:
    result = operation()
except Exception as e:
    log.error("failed")  # logs without re-raising or handling

# REQUIRED — specific exception, logged, re-raised or explicitly handled
try:
    result = operation()
except SpecificException as e:
    log.error("operation.failed", error=str(e), error_type=type(e).__name__)
    raise DomainException(f"Context-rich message: {e}") from e
```

#### 3.2.2 Magic Values

A magic value is any literal that carries meaning that is not self-evident from context.

```python
# FORBIDDEN — magic numbers
if importance > 0.8:           # What is 0.8?
    ...
if token_count > 4096:         # Why 4096?
    ...
if retry_count < 3:            # Why 3?
    ...
await asyncio.sleep(0.5)       # Why half a second?
if len(content) > 500:         # Why 500?
    ...

# REQUIRED — named constants at module level
IMPORTANCE_THRESHOLD_HIGH: float = 0.8
MAX_CONTEXT_TOKENS: int = 4096
MAX_RETRY_ATTEMPTS: int = 3
RETRY_BASE_DELAY_SECONDS: float = 0.5
TOOL_INPUT_PREVIEW_LENGTH: int = 500

if importance > IMPORTANCE_THRESHOLD_HIGH:
    ...
```

**Exceptions to the magic value rule:**
- `0` and `1` in arithmetic context where meaning is obvious
- `-1` as a sentinel value when immediately obvious from context
- HTTP status codes where the meaning is universally understood (`200`, `404`, `500`)
- Timeout values that are configuration values (use `config.llm.request_timeout_seconds`)

#### 3.2.3 Temporary and Placeholder Code

```python
# FORBIDDEN — TODO as implementation
def calculate_importance(content: str) -> float:
    # TODO: implement proper importance calculation
    return 0.5

# FORBIDDEN — FIXME as implementation
async def embed(text: str) -> List[float]:
    # FIXME: this is slow, fix later
    return [0.0] * 1024

# FORBIDDEN — HACK comment
def get_model(tier: ModelTier) -> str:
    # HACK: hardcoded because the router isn't ready yet
    return "claude-sonnet-4-6"

# FORBIDDEN — commented-out code blocks
# result = await old_implementation()
# if result:
#     return result.value

# FORBIDDEN — pass as implementation
async def consolidate(self, session_id: str) -> ConsolidationReport:
    pass  # Not implemented yet

# FORBIDDEN — ellipsis as implementation in non-stub files
async def recall(self, query: str) -> ContextPackage:
    ...  # Implement later
```

**Acceptable alternatives:**
- A function that is not ready to be implemented does not exist in the codebase. Create it when implementing it.
- If a function must exist as a defined interface before implementation, it raises `NotImplementedError` with a specific message and the ADR that defines when it will be implemented.
- Documentation of known gaps belongs in `docs/architecture/decisions/` as a future ADR, not in code comments.

```python
# ACCEPTABLE — explicit not-implemented with reference
async def recall(self, query: str) -> ContextPackage:
    """
    Retrieves relevant memories using hybrid search.

    Implementation: Milestone 1.5 — Memory System
    Status: Awaiting prerequisite Milestone 1.4 (SQLite Schema)
    """
    raise NotImplementedError(
        "MemoryAPI.recall() is implemented in Milestone 1.5. "
        "See docs/phases/PHASE_1_FOUNDATION.md"
    )
```

#### 3.2.4 Hardcoded Configuration

```python
# FORBIDDEN — hardcoded URLs
client = QdrantClient(host="localhost", port=6333)

# FORBIDDEN — hardcoded model names in application logic
response = await router.complete(messages, model="claude-opus-4-6")

# FORBIDDEN — hardcoded timeouts
await asyncio.wait_for(operation(), timeout=30.0)

# FORBIDDEN — hardcoded file paths
db_path = "data/aether.db"

# FORBIDDEN — hardcoded dimensions
embedding_dim = 1024

# REQUIRED — all values from configuration
config = get_config()
client = QdrantClient(host=config.qdrant.host, port=config.qdrant.port)
await asyncio.wait_for(operation(), timeout=config.llm.request_timeout_seconds)
db_path = config.data_dir / "aether.db"
embedding_dim = config.memory.embedding_dimension
```

**Exception:** Constants that are truly invariant and have architectural significance (not operational configuration) may be defined as module-level constants, not read from config. Example: `EMBEDDING_DIMENSION = 1024` is an architectural constant that must match the Qdrant collection configuration. It is defined once and used everywhere, but it is NOT read from runtime config because changing it at runtime would corrupt the vector store.

#### 3.2.5 Architecture Bypasses

```python
# FORBIDDEN — direct provider access in an agent
from anthropic import Anthropic
client = Anthropic()
response = client.messages.create(...)

# FORBIDDEN — direct database access in an agent
from qdrant_client import QdrantClient
client = QdrantClient(...)
results = client.search(...)

# FORBIDDEN — tool called directly, bypassing registry
from aether.tools._implementations.search_tools import WebSearchTool
tool = WebSearchTool()
result = await tool.execute(input)

# FORBIDDEN — memory accessed without going through MemoryAPI
from aether.memory._stores.sqlite_store import SQLiteMemoryStore
store = SQLiteMemoryStore()
records = await store.get_all()

# REQUIRED — all access through defined module interfaces
await self._invoke_tool("web_search", {"query": "..."})   # Via BaseAgent helper
context = await self._recall("query")                       # Via BaseAgent helper
response = await llm_router.complete(messages, ModelTier.STANDARD)  # Via router
```

#### 3.2.6 Rookie Mistakes

The following patterns indicate insufficient care and are rejected on code review:

```python
# FORBIDDEN — mutable default arguments
def process(items: List[str] = []) -> None: ...     # Shared across calls
def configure(options: dict = {}) -> None: ...      # Shared across calls

# REQUIRED
def process(items: Optional[List[str]] = None) -> None:
    if items is None:
        items = []

# FORBIDDEN — comparison to True/False/None with ==
if result == True: ...       # Use: if result:
if result == False: ...      # Use: if not result:
if result == None: ...       # Use: if result is None:
if result != None: ...       # Use: if result is not None:

# FORBIDDEN — bare string exception
raise Exception("Something went wrong")     # Untyped, uncatchable specifically

# REQUIRED — domain-specific exception
raise MemoryRetrievalError("Vector search failed: timeout after 30s")

# FORBIDDEN — sleep in async context
import time
time.sleep(1.0)               # Blocks the event loop

# REQUIRED
await asyncio.sleep(1.0)

# FORBIDDEN — not using context manager for resources
file = open("path/to/file", "r")
content = file.read()
file.close()                  # Not called if exception occurs

# REQUIRED
async with aiofiles.open("path/to/file", "r") as file:
    content = await file.read()

# FORBIDDEN — float equality comparison
if embedding_score == 0.8: ...           # Floating point imprecision

# REQUIRED
if abs(embedding_score - 0.8) < 1e-9: ...   # Or use math.isclose()

# FORBIDDEN — catching broad Exception when specific is possible
try:
    await qdrant_client.search(...)
except Exception as e:                    # Too broad
    log.error("search failed", error=str(e))

# REQUIRED — catch the specific exception
try:
    await qdrant_client.search(...)
except UnexpectedResponse as e:
    log.error("qdrant.search.failed", status=e.status_code, error=str(e))

# FORBIDDEN — wildcard imports
from aether.memory import *              # Never
from typing import *                     # Never

# FORBIDDEN — single-letter variable names outside tight iteration
d = get_config()                         # What is d?
r = await router.complete(...)           # What is r?
m = await memory_api.remember(...)       # What is m?

# REQUIRED — descriptive names
config = get_config()
llm_response = await router.complete(...)
memory_id = await memory_api.remember(...)

# FORBIDDEN — unused variables
result = await operation()               # result never used
_, data = parse_response()              # underscore for intentional ignore is fine, but
                                        # assigning to named variable and not using it is not

# FORBIDDEN — string concatenation in loops
result = ""
for item in items:
    result += item + ", "                # Quadratic time complexity

# REQUIRED
result = ", ".join(items)
```

### 3.3 Mandatory Typing Standards

**Standard:** Full strict typing. `mypy --strict` must pass with zero errors on all production code.

**Annotations required on:**
- All function parameters (public and private)
- All function return types (public and private)
- All class attributes at class level (not just `__init__`)
- All module-level variables (when not obviously typed)

**`Any` policy:**
The type `Any` is permitted only when:
- Interfacing with a third-party library that has incomplete type stubs
- Explicitly justified in an inline comment: `# type: ignore[misc] — litellm returns untyped dict`
- The scope of `Any` is minimal and contained within a private adapter function

Using `Any` to avoid thinking about types is forbidden.

**Optional types:**
```python
# FORBIDDEN — implicit Optional
def process(callback = None): ...       # Type not declared

# FORBIDDEN — outdated Optional syntax (acceptable but deprecated)
from typing import Optional
def process(callback: Optional[Callable] = None): ...

# REQUIRED — modern union syntax (Python 3.10+)
def process(callback: Callable | None = None): ...
```

**Collections:**
```python
# FORBIDDEN — bare collection types
def process(items: list) -> dict: ...   # Too generic

# REQUIRED — parameterized types
def process(items: list[str]) -> dict[str, float]: ...
```

**Literal types:**
```python
# REQUIRED — for fixed-value parameters
def set_status(status: Literal["pending", "active", "completed"]) -> None: ...
```

### 3.4 Mandatory Testing Standards

**Principle:** Tests are not a bureaucratic requirement. They are the specification expressed as code. A function without tests is a function whose behavior is undefined.

**Required tests by code type:**

| Code Type | Required Tests | When Required |
|---|---|---|
| New public function | Unit test | Before PR merge |
| New agent | Unit test + integration test | Before PR merge |
| New tool | Unit test + integration test | Before PR merge |
| New event type | Contract test | Before PR merge |
| Database schema change | Migration test (up + down) | Before PR merge |
| API signature change | Contract test update | Before PR merge |
| Bug fix | Regression test that would have caught the bug | Before PR merge |
| Refactor | Existing tests must still pass | Before PR merge |

**Coverage targets by phase:**

| Phase | Target | Scope |
|---|---|---|
| Phase 1 | Critical path coverage | memory, llm router, agent runtime |
| Phase 2 | 70% line coverage | all stable modules |
| Phase 3 | 75% line coverage | all stable modules |
| Phase 4+ | 80% line coverage | all stable modules |

Coverage below target is not a blocking violation in Phase 1 for non-critical modules. It is tracked and addressed at phase completion.

**Test naming convention:**
```
test_{unit_under_test}_{condition}_{expected_outcome}

Examples:
test_memory_api_recall_returns_relevant_memories_for_semantic_query
test_llm_router_forces_local_tier_when_daily_budget_exceeded
test_conversation_agent_stores_user_name_to_memory_after_introduction
```

**Test isolation requirement:**
Every unit test must be independent. Tests must not depend on execution order. Tests must not share mutable state. Each test sets up its own fixtures and tears them down.

**Prohibited test patterns:**
```python
# FORBIDDEN — test that always passes
def test_something():
    assert True

# FORBIDDEN — test with no assertion
def test_memory_store():
    memory = MemoryRecord(...)
    # No assertion — this tests nothing

# FORBIDDEN — test with assert False commented out
def test_recall():
    result = memory_api.recall("query")
    # assert result is not None  (commented out for "now")

# FORBIDDEN — test that catches all exceptions
def test_agent():
    try:
        result = agent.execute(task)
        assert result is not None
    except Exception:
        pass  # Test passes even if agent crashes
```

### 3.5 Mandatory Logging Standards

**Principle:** Every significant operation must produce a log record. The system must be debuggable without attaching a debugger. Log analysis must be possible without reading source code.

**Logger instantiation:**
```python
import structlog
log = structlog.get_logger(__name__)
```

One logger per module, instantiated at module level. Not passed as a function argument. Not stored on objects.

**What must be logged:**

| Category | Level | Required Fields |
|---|---|---|
| Session start/end | INFO | session_id, mode, timestamp |
| Agent execution start/end | INFO | run_id, agent_name, task_description |
| LLM call | INFO | provider, model, tier, tokens, cost_usd, duration_ms |
| Memory store | INFO | memory_id, memory_type, importance |
| Memory recall | INFO | query, memories_found, duration_ms |
| Tool execution | INFO | tool_name, success, duration_ms |
| Any external API call | INFO | service, endpoint, duration_ms, status |
| Any exception caught | ERROR | error, error_type, stack context |
| Budget threshold | WARNING | tier, percent_used, amount_usd |
| Retried operation | WARNING | operation, attempt, max_attempts, reason |
| Service startup | INFO | service_name, version, config summary |
| Service shutdown | INFO | service_name, reason, duration_seconds |

**Log message format:**
```python
# CORRECT — event name as first argument, key-value context pairs
log.info("memory.recall.completed",
    query=query[:50],           # Truncate long values
    memories_found=len(results),
    duration_ms=elapsed_ms,
    session_id=context.session_id
)

log.error("qdrant.search.failed",
    error=str(e),
    error_type=type(e).__name__,
    collection="episodic_memory",
    query_length=len(query)
)

# FORBIDDEN — unstructured messages
log.info(f"Retrieved {len(results)} memories in {elapsed_ms}ms")
log.error("Qdrant search failed: " + str(e))
log.info("Done")
```

**Log event naming:** Same convention as event bus: `domain.entity.action`

**What must NOT be logged:**
- Full content of memories (use truncated preview: `content[:100]`)
- API keys or secrets (even partial)
- Full conversation content (use `message_count` and `role` instead)
- Stack traces for expected failures (use ERROR level for unexpected failures only)
- Passwords, tokens, or credentials of any kind

### 3.6 Mandatory Documentation Standards

**Principle:** Code is read far more often than it is written. Documentation is part of the implementation. Undocumented public code is incomplete code.

**Module-level docstring (required for every public module):**
```python
"""
Memory API — Public interface for all memory operations.

This module is the sole entry point for memory read and write operations
throughout Aether. No other module accesses the memory storage backends directly.

Public interface:
    MemoryAPI.remember() — Store a new memory
    MemoryAPI.recall()   — Retrieve relevant memories
    MemoryAPI.forget()   — Remove a specific memory
    MemoryAPI.consolidate() — Process session into long-term memory

Architecture boundary:
    This module owns: aether/memory/_stores/, aether/memory/_retrieval/
    This module may not be bypassed. See ADR-010 Section 3.5.
"""
```

**Class-level docstring (required for all public classes):**
```python
class MemoryAPI:
    """
    Sole interface for all memory operations in the Aether system.

    Provides a consistent abstraction over the hybrid storage backend
    (SQLite for structured data, Qdrant for vector search). Callers
    never interact with storage backends directly.

    Thread safety: All methods are async-safe. Multiple concurrent calls
    are permitted. Internal locking is managed by the storage backends.

    Usage:
        memory = MemoryAPI(config=config.memory)
        await memory.initialize()
        memory_id = await memory.remember("User prefers Python", MemoryType.PREFERENCE, 0.8)
        context = await memory.recall("user programming preferences")
    """
```

**Function-level docstring (required for all public functions):**
```python
async def recall(
    self,
    query: str,
    k: int = 10,
    filters: MemoryFilter = MemoryFilter(),
    token_budget: int = 4096
) -> ContextPackage:
    """
    Retrieves relevant memories using hybrid vector and keyword search.

    Combines semantic similarity search (Qdrant cosine similarity) with
    full-text keyword search (SQLite FTS5), reranks results by a weighted
    score combining similarity, recency, and importance, and assembles
    a ContextPackage that respects the token budget.

    Updates last_accessed_at and access_count for each retrieved memory.

    Args:
        query: Natural language description of what to retrieve.
            Used for both vector embedding and keyword tokenization.
        k: Maximum number of memories to return after reranking.
            The retrieval pipeline fetches more candidates internally
            and reduces to k after scoring.
        filters: Optional constraints on memory_type, date range, tags,
            entities, confidence, and importance. See MemoryFilter.
        token_budget: Maximum estimated token count for the assembled
            formatted_context string. Memories are excluded from the
            context string (but still returned in ContextPackage.memories)
            if including them would exceed the budget.

    Returns:
        ContextPackage containing the ranked memories and a pre-formatted
        context string ready for injection into an LLM prompt.

    Raises:
        MemoryRetrievalError: If both vector search and keyword search fail.
            Partial failures (one backend unavailable) are tolerated —
            results from the available backend are returned with a warning.
    """
```

**Inline comments — required for non-obvious logic:**
```python
# WRONG — comment that restates the code
# Increment the counter
counter += 1

# WRONG — no comment on genuinely non-obvious logic
score = (0.6 * similarity) + (0.3 * recency_weight) + (0.1 * importance)

# CORRECT — comment explains the WHY, not the WHAT
# Rerank score: weighted combination of semantic similarity (dominant),
# recency (secondary), and user-assigned importance (minor tiebreaker).
# Weights determined empirically during Phase 1 testing — see ADR-012.
score = (0.6 * similarity) + (0.3 * recency_weight) + (0.1 * importance)
```

**ADR requirement:**
Any decision that changes an architectural interface, adds a new dependency, introduces a new pattern, or reverses a prior decision requires an ADR document before the code is written.

## 4. QUALITY GATES

Quality gates are mandatory checkpoints. Code does not advance to the next stage without passing all gates for that stage. There are no exceptions. There are no waivers.

---

### Gate Q-1: Syntactic Quality Gate
**Stage:** Pre-commit hook (runs automatically on every commit attempt)  
**Blocks:** The commit itself

**Required checks:**

| Check | Command | Pass Criterion |
|---|---|---|
| Style and lint | `ruff check .` | Exit code 0, zero warnings |
| Format | `ruff format --check .` | Exit code 0 |
| Type safety | `mypy aether/ services/ --strict` | Exit code 0, zero errors |
| Forbidden patterns | grep scan for patterns in ADR-010 Section 3 | Zero matches |

**Failure behavior:** Pre-commit hook blocks the commit. The developer corrects violations before committing. AI-generated code that fails this gate is not committed. The fix is applied by the developer, not by requesting another AI generation.

---

### Gate Q-2: Architecture Compliance Gate
**Stage:** CI pipeline (runs on every push to any branch)  
**Blocks:** Pull request merge to `develop` or `main`

**Required checks:**

| Check | Command | Pass Criterion |
|---|---|---|
| Boundary enforcement | `lint-imports` | Zero violations |
| No circular imports | `python -c "import aether"` | No ImportError |
| Public API completeness | Contract tests | All pass |
| Event schema validation | Contract tests | All pass |

**Additional manual verification (at PR review):**
- Every new module has `__init__.py` with explicit `__all__`
- Every new module's public API matches the specification in the technical spec
- No new inter-module import paths that are not in the approved boundary list

**Failure behavior:** PR cannot be merged. The boundary violation is corrected and the PR is re-reviewed. Partial exceptions (merging with a known violation to be fixed later) are not permitted.

---

### Gate Q-3: Testing Gate
**Stage:** CI pipeline  
**Blocks:** Pull request merge to `develop`

**Required checks:**

| Check | Command | Pass Criterion |
|---|---|---|
| Unit tests | `pytest tests/unit/ -x --tb=short` | Exit code 0, all pass |
| Contract tests | `pytest tests/contracts/ -x --tb=short` | Exit code 0, all pass |
| Architecture tests | `pytest tests/architecture/ -x --tb=short` | Exit code 0, all pass |
| Coverage (Phase 2+) | `pytest --cov=aether --cov-fail-under=70` | Coverage threshold met |

**Integration tests** (`pytest tests/integration/`) run on:
- Merge to `develop`
- Milestone completion verification
- Pre-release

Integration tests do not run on every feature branch push (requires real services).

**New code testing requirements:**
- New public function: minimum one unit test covering the primary success path
- New agent: unit test + integration test for a complete execution
- New tool: unit test for success path, unit test for invalid input, unit test for failure path
- Bug fix: regression test that would have detected the bug

**Failure behavior:** PR cannot be merged. Missing tests must be written by the developer. The fact that AI-generated code does not include tests does not exempt the code from the testing requirement — the developer writes the tests.

### Gate Q-4: Documentation Gate
**Stage:** PR review (manual check)  
**Blocks:** Pull request merge to `main`

**Checklist:**

```
Documentation Gate — verify all items before approving merge to main:

Public API Documentation:
  [ ] All new public functions have Google-style docstrings
  [ ] All new public classes have class-level docstrings
  [ ] All new public modules have module-level docstrings
  [ ] All docstrings describe WHAT the function does, not HOW it does it
  [ ] All docstrings include Args, Returns, and Raises sections where applicable

Architectural Documentation:
  [ ] Any new ADR-worthy decision has an ADR document in docs/architecture/decisions/
  [ ] Any change to an existing module's public API is reflected in V1_TECHNICAL_SPECIFICATION.md
  [ ] Any new event type is added to the event catalog in V1_TECHNICAL_SPECIFICATION.md Section 7
```

### 5.1 The Review Process for a Solo Developer

## 8. CODE COMPLEXITY STANDARDS

### 8.1 Why Complexity Limits Exist

Complexity accumulates gradually. No single function is "too long" in isolation — but across a 5-year project with AI-assisted generation, the aggregate effect of functions that are 70 lines, files that are 800 lines, and nesting that reaches 6 levels deep is a codebase that becomes unmaintainable before Phase 5 is complete. Quantitative limits prevent this accumulation. They are enforced by tooling, not by human judgment in the moment.

### 8.2 Function Length Limit — 50 Executable Lines

**Limit:** 50 executable lines per function or method.  
**Measured as:** Lines that execute — not counting docstrings, blank lines, or comment-only lines.  
**Enforced by:** Code review checklist (automated measurement via `ruff`).  
**Applies to:** All functions in `aether/`, `services/`, and `migrations/`.

**Exception:** Test functions may exceed 50 lines when the excess consists entirely of additional explicit assertions on a single logical behavior. Test functions may not use this exception to contain multiple logical behaviors in one function.

**Action when exceeded:** Extract a named private helper function. The name must describe what the extracted logic does — `_validate_memory_importance()`, not `_helper()` or `_process()`.

```python
# FORBIDDEN — function that exceeds 50 executable lines
async def recall(self, query: str, k: int = 10) -> ContextPackage:
    # 80 lines of mixed retrieval, ranking, and formatting logic
    ...

# REQUIRED — extracted and named
async def recall(self, query: str, k: int = 10) -> ContextPackage:
    candidates = await self._retrieve_candidates(query, k * 2)
    ranked = self._rank_by_composite_score(candidates, query)
    return self._assemble_context_package(ranked[:k])

async def _retrieve_candidates(self, query: str, limit: int) -> List[ScoredMemory]:
    ...  # focused retrieval logic

def _rank_by_composite_score(self, candidates: List[ScoredMemory], query: str) -> List[ScoredMemory]:
    ...  # focused ranking logic

def _assemble_context_package(self, memories: List[ScoredMemory]) -> ContextPackage:
    ...  # focused assembly logic
```

### 8.3 File Size Limit — 500 Lines

**Limit:** 500 total lines per Python file.  
**Measured as:** All lines including docstrings, comments, and blank lines.  
**Exception:** Alembic migration files in `migrations/versions/` — schema DDL is inherently verbose and atomic. Migration files have no line limit.

**Action when exceeded:** Split the file at clear domain boundaries. Each resulting file must have a focused, single responsibility. If a file cannot be split without creating incoherent fragments, the excess is a signal that the module's responsibilities are too broad and require an architectural review.

**Ruff enforcement:** Add to `pyproject.toml`:
```toml
[tool.ruff.lint]
max-doc-length = 100  # Existing
# File length is tracked via code review, not ruff (ruff does not enforce file length)
```
File length is verified in the code review checklist, not automated CI. The manual check is: `wc -l {file}` or IDE line count.

### 8.4 Cyclomatic Complexity Limit — 10 Per Function

**Limit:** Cyclomatic complexity of 10 per function.  
**Measured as:** The number of linearly independent paths through the function. Each `if`, `elif`, `for`, `while`, `except`, `with`, `and`, `or` adds 1 to complexity.  
**Enforced by:** Ruff rule C901. Add to `pyproject.toml`:

```toml
[tool.ruff.lint]
select = ["C901"]  # Add to existing select list

[tool.ruff.lint.mccabe]
max-complexity = 10
```

**Why 10:** A function with cyclomatic complexity of 10 requires a minimum of 10 test cases for full branch coverage. Functions above 10 are exponentially harder to test completely and exponentially harder to reason about.

**Action when exceeded:** Extract decision logic into named private functions with descriptive names. Each extracted function should reduce complexity by encapsulating one coherent decision.

### 8.5 Class Size Limit — 300 Lines

**Limit:** 300 total lines per class definition.  
**No exceptions.** A class exceeding 300 lines carries multiple responsibilities. Split by responsibility — each class does one thing.  
**Action when exceeded:** Apply the Single Responsibility Principle. Identify distinct responsibilities within the class and extract each into a dedicated class with a clear name.

### 8.6 Nesting Depth Limit — 4 Levels

**Limit:** 4 levels of indentation nesting within any function body.  
**Applies to:** if/elif/else, for, while, with, try/except nesting.  
**Does not count:** The function definition itself (level 0 for the body).

```python
# FORBIDDEN — 5 levels of nesting
async def process(items: list) -> dict:
    result = {}
    if items:                         # level 1
        for item in items:            # level 2
            if item.valid:            # level 3
                for chunk in item:    # level 4
                    if chunk.data:    # level 5 — FORBIDDEN
                        result[chunk.id] = chunk.data
    return result

# REQUIRED — extract to reduce nesting
async def process(items: list) -> dict:
    if not items:
        return {}
    return {chunk.id: chunk.data for item in items
            for chunk in item if item.valid and chunk.data}
```

## 9. ERROR MESSAGE QUALITY STANDARDS

### 9.1 The Gap This Section Fills

Section 3.2.1 defines what *wrong* exception handling looks like: bare `except`, swallowed exceptions, exceptions without logging. This section defines what *correct* error messages must contain. An exception can be correctly typed, correctly logged, and correctly re-raised while still carrying a message so vague it is useless for diagnosis.

### 9.2 Error Message Requirements

Every error message — whether in an exception, a log entry, or a user-facing response — must satisfy these requirements:

**Requirement E-1: ACTIONABLE**  
The message tells the receiver what to do, not just what went wrong.

```python
# FORBIDDEN — not actionable
raise MemoryRetrievalError("Qdrant search failed")

# REQUIRED — actionable
raise MemoryRetrievalError(
    "Qdrant vector search failed after 3 retries. "
    "Verify Qdrant is running: curl http://localhost:6333/health. "
    "Check logs for connection details."
)
```

**Requirement E-2: SPECIFIC**  
The message names the offending value, parameter, or component — not just the category.

```python
# FORBIDDEN — not specific
raise ValueError("Invalid importance value")

# REQUIRED — specific
raise MemoryValidationError(
    f"importance must be between 0.0 and 1.0, received: {importance!r}"
)
```

**Requirement E-3: ACCURATE**  
The message describes what *actually* failed, not what was *expected* to succeed.

```python
# FORBIDDEN — describes expectation, not failure
raise LLMTimeoutError("Expected LLM response within 60 seconds")

# REQUIRED — describes what happened
raise LLMTimeoutError(
    f"LLM call to {model!r} timed out after {timeout_seconds}s. "
    f"Tier: {tier.value}. Configured limit: {config.llm.request_timeout_seconds}s"
)
```

### 9.3 Developer-Facing vs User-Facing Error Distinction

**Developer-facing errors** appear in:
- Exception messages (propagated within `aether/` and `services/`)
- Structlog ERROR-level entries
- Stack traces in development mode

Developer-facing errors MAY include:
- Exception class names and error codes
- Internal component names and module paths
- Configuration key names and their values
- Query strings, parameters, and response bodies (truncated)
- Redis keys, database table names

**User-facing errors** appear in:
- TTS-synthesized voice responses
- CLI display output
- Future dashboard error states

User-facing errors MUST NOT include:
- Python exception class names (`MemoryRetrievalError`, `QdrantException`)
- Internal component paths or module names
- Stack traces or line numbers
- Database identifiers or raw query results
- API keys or credentials (even if obscured)

User-facing errors MUST:
- Use plain English readable without technical knowledge
- Indicate whether the issue is temporary ("I'm having trouble connecting") or requires action ("I couldn't find that")
- Be recoverable within the conversation where possible

```python
# Developer-facing (raised internally):
raise MemoryRetrievalError(
    f"Qdrant search on collection 'episodic_memory' failed: {e}. "
    f"Query: '{query[:50]}', k={k}"
)

# User-facing (when ConversationAgent catches this):
response_text = (
    "I'm having trouble accessing my memory right now. "
    "I can still help you, but I may not remember our previous conversations."
)
```

### 9.4 Exception Class Hierarchy

All domain exceptions inherit from a single base class. This enables callers to catch all Aether-domain errors without catching Python builtins.

**Base class:** `AetherError(Exception)` — defined in `aether/core/exceptions.py`

**Naming convention:** `{Domain}{Issue}Error`

**Required exception classes (Phase 1):**

```
AetherError (base)
├── ConfigurationError          — missing or invalid configuration
├── MemoryError (aether)        — all memory subsystem failures
│   ├── MemoryRetrievalError    — recall/search failures
│   ├── MemoryStorageError      — remember/write failures
│   └── MemoryValidationError   — invalid memory parameters
├── LLMError                    — all LLM subsystem failures
│   ├── LLMTimeoutError         — request timeout
│   ├── LLMProviderError        — provider-side failures
│   └── LLMBudgetError          — budget exceeded with no fallback
├── ToolError                   — all tool execution failures
│   ├── ToolNotFoundError        — tool name not in registry
│   ├── ToolExecutionError       — tool.execute() raised
│   └── ToolPermissionError      — permission check failed
├── AgentError                  — all agent execution failures
│   ├── AgentTimeoutError        — agent exceeded time limit
│   └── AgentIterationError      — agent exceeded iteration limit
└── VoiceError                  — all voice pipeline failures
    ├── VoiceTranscriptionError  — STT failure
    └── VoiceSynthesisError      — TTS failure
```

**Forbidden exception raising patterns in domain code:**

```python
# FORBIDDEN — raw Python built-in in domain code
raise ValueError("invalid tier")
raise RuntimeError("something went wrong")
raise Exception("failed")

# REQUIRED — domain-specific subclass
raise LLMError(f"Invalid model tier: {tier!r}. Expected one of: {list(ModelTier)}")
```

Python built-in exceptions (`ValueError`, `TypeError`, `KeyError`) are permitted *only* in validation functions whose sole purpose is input validation, and only when Pydantic validation is insufficient.

### 9.5 Error Code Convention

For errors that will appear in logs at high volume or that require programmatic handling, an `error_code` string is included:

```python
# Format: DOMAIN_ISSUE in SCREAMING_SNAKE_CASE
raise MemoryRetrievalError(
    "Vector search failed",
    error_code="MEMORY_QDRANT_UNAVAILABLE"
)
```

Error codes are defined as module-level constants in the exception module. They are stable identifiers that do not change when error message text is improved.

## 10. PERFORMANCE BASELINE STANDARDS

### 10.1 Why Baselines Are Required

Performance degradation in a long-running system is invisible without a documented baseline. A memory recall operation that takes 85ms at Phase 1 completion and 420ms at Phase 4 completion has degraded significantly — but without the Phase 1 measurement, that degradation is not detectable. "It seems slower" is not engineering. A documented baseline is.

### 10.2 Mandatory Baseline Documentation

**At each phase completion**, before the GO decision is recorded, a performance baseline document is created and committed:

**Location:** `docs/performance/phase-{N}-baseline.md`  
**Created at:** Phase GO decision  
**Compared at:** Each subsequent phase GO decision

**Measurement method:**
1. Ensure the system has been running for at least 30 minutes (warm state, not cold start)
2. Run each measured operation 10 times
3. Record all 10 durations in milliseconds
4. Calculate p50 (median — sort, take value at position 5)
5. Calculate p95 (sort, take value at position 9 of 10)
6. Record to the baseline document

### 10.3 Paths Requiring Measurement at Phase 1

| Path | Operation | Measurement | Target p50 | Target p95 |
|---|---|---|---|---|
| Memory recall | `MemoryAPI.recall("test query", k=10)` | End-to-end ms | < 150ms | < 400ms |
| Memory store | `MemoryAPI.remember("test content", ...)` | End-to-end ms | < 200ms | < 500ms |
| LLM — LOCAL | Ollama phi4-mini 50-token completion | End-to-end ms | < 3000ms | < 6000ms |
| LLM — CHEAP | Gemini Flash 50-token completion | End-to-end ms | < 800ms | < 1500ms |
| LLM — STANDARD | Claude Sonnet 50-token completion | End-to-end ms | < 1500ms | < 3000ms |
| Voice end-to-end | Wake word confirmed → first audio byte | End-to-end ms | < 1500ms | < 2500ms |
| Agent — conversation | Simple fact recall question | End-to-end ms | < 3000ms | < 5000ms |
| Embedding | Single 50-word text | End-to-end ms | < 300ms | < 600ms |

### 10.4 Baseline Document Format

```markdown
# Aether Performance Baseline — Phase {N}

**Date:** YYYY-MM-DD  
**Hardware:** Intel i7-13700HX · RTX 4050 6GB VRAM · 16GB DDR5  
**System State:** Warm (30+ minutes running)  
**Measurement:** 10 runs per path, p50 and p95 reported  

## Baseline Results

| Path | All 10 Measurements (ms) | p50 | p95 | Target p50 | Status |
|---|---|---|---|---|---|
| Memory recall | 82,91,88,79,95,84,77,90,88,86 | 86 | 95 | <150 | PASS |

## Comparison to Prior Phase

| Path | Phase N-1 p50 | Phase N p50 | Change | Status |
|---|---|---|---|---|
| Memory recall | 86ms | 94ms | +9% | PASS |

## Notes

{Any observations about conditions during measurement, anomalies, or known influences.}
```

### 10.5 Degradation Policy

| Degradation | Classification | Required Action |
|---|---|---|
| > 20% from prior baseline | P2 Technical Debt | Open DEBT_REGISTER.md entry, investigate within current phase |
| > 50% from prior baseline | P1 Technical Debt | Investigate and resolve before Phase N+1 GO decision |
| > 100% from prior baseline | Phase Gate block | Phase N+1 does not begin until degradation is resolved |

**Important:** Performance targets in Section 10.3 are Phase 1 targets. Targets may be updated in future phases if hardware changes or if the measurement reveals the target was calibrated incorrectly. Target updates require a CHANGELOG.md entry with justification.
